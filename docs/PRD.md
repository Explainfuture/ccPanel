# ccPanel 产品需求文档 v1.1

日期：2026-10-22。状态：基于已确认方案的实现基线；参数为首版默认设计，须经浏览器验证、容量压测和部署检查后发布。关联：[架构 v2 与流程图](ARCHITECTURE.md)、[实施计划](PLAN.md)。本文不代表功能已完成，不包含服务器凭据。

v1.1 范围澄清：一个公司就是一个租户（tenant/工作区）。同公司所有有效成员均可查看公司全部项目与分析数据，只限制跨公司访问；不实现部门、门店、员工归属或项目成员白名单等公司内部数据权限。

## 1. 产品目标与范围

为开发者和产品人员提供可自托管的事件采集与产品分析平台：业务网站安装 TypeScript SDK 后，能记录行为、关联用户，并通过图表分析趋势、转化与留存。优先保证数据可解释、重试不重复计数、故障可观察和可恢复。

首版不追求完整 Mixpanel 等价，不包含会话录像、热力图、自动 DOM 全量采集、A/B 实验分流、移动端原生 SDK、任意 SQL 控制台、计费系统及跨地域多活。Redis、ClickHouse、Kubernetes 不作为首期依赖。

| 角色 | 核心任务 |
|---|---|
| 项目管理员 | 创建项目、管理凭证和成员、配置事件规范与保留策略 |
| 业务开发者 | 安装 SDK、定义事件、查看调试与投递错误 |
| 分析人员 | 筛选事件、分析用户行为、保存报表和仪表盘 |
| 运维人员 | 监控接入/积压、处理 DLQ、备份恢复和容量管理 |

首版后台使用 React、shadcn/ui、Tailwind CSS；Hono 提供接入与管理/查询 API；Kafka 缓冲；TypeScript Worker 写 PostgreSQL；pnpm workspace 管理 SDK 和应用。Kafka 与数据库只在私网开放。

## 2. 发布顺序与核心用户路径

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| M1 接入闭环 | 项目与凭证、Browser SDK、Node SDK 基础接口、事件列表、投递监控 | SDK 到 PG 可对账，重复和崩溃重放不增加计数 |
| M2 基础分析 | 趋势、属性筛选、用户时间线、保存报表与仪表盘 | 固定测试数据的图表与明细一致 |
| M3 产品分析 | 身份关联、漏斗、留存、简单分群 | 本文定义的分析口径全部有基准数据验收 |
| M4 试运行 | 资源限额、故障注入、DLQ 操作、恢复演练、容量报告 | 未通过容量门槛不接真实生产流量 |

用户路径：创建项目 → 获取公开写入凭证 → 安装并初始化 SDK → 显式调用 track → 在接入调试页查看事件 → 创建分析报表 → 保存到仪表盘。后台必须区分本地排队、Kafka 已接收、PG 已入库、聚合已更新，不能将它们统一显示为“成功”。

## 3. 事件与身份模型

| 字段 | 规则 |
|---|---|
| tenant_id | 公司 ID，由服务端从有效写入凭证确定；客户端不得自行指定归属 |
| project_id | 公司下的项目 ID，由接入凭证确定并验证归属 |
| event_id | UUID v4；事件创建时生成，新操作新 ID，所有重试复用 |
| event_name | 必填，1–128 字符；建议稳定 snake_case，不把订单号拼进名称 |
| distinct_id | 1–256 字符，当前登录用户 ID 或匿名 ID；非用户名/姓名拼接生成的 event ID |
| anonymous_id | 浏览器首次初始化生成并持久保存的随机 ID；登录后仍可随事件携带 |
| event_time | SDK 创建事件时的 UTC 时间；重试不改变；用户可显式传入受校验的业务时间 |
| received_at | 服务端本次接收时间；去重保留首次成功落库版本，不作为载荷冲突比较依据 |
| properties | 可选 JSON 对象，最多 100 个顶层键，最多 5 层；不接受函数、循环引用、NaN/Infinity |
| context | SDK 名称/版本、来源 browser/node、规范化页面路径等；上下文在创建时快照 |
| schema_version | 通用信封与项目事件规则版本，供校验和故障排查 |

示例：同一用户在页面 A 点购买、在页面 B 点收藏，distinct_id 相同，event_name 和 properties 按行为变化，event_id 必须不同。同 ID 同内容是重试；同 ID 不同内容是冲突，不能覆盖已保存事件。

通用 SDK 不写死业务事件。项目可定义“事件名 → 必填属性、属性类型、描述、版本”；开发者可用对应 TypeScript 类型获得自动补全，接入端仍做运行时校验。首版提供宽松/严格两种项目模式：宽松模式接收符合通用格式的未知事件并标记未登记；严格模式拒绝未知事件或缺失业务必填字段。类型定义导出先提供手工可下载文件，不依赖自动代码生成服务。

身份规则：未登录使用匿名 ID；identify(user_id) 设置后续事件的登录身份，并上报可审计的匿名→登录身份关联记录，该记录也有自己的 event_id 并走相同队列。旧待发事件不改写身份。一个匿名 ID 首版只允许关联一个用户；发现冲突拒绝合并并告警，不自动合并两个登录用户。reset/logout 清空当前身份并生成新的匿名 ID，但不把此前待发事件改归新用户。共享设备与多标签页身份冲突要可调试；身份变化通过跨标签通知同步，边界时刻以各事件创建时快照为准。

分析使用规范化身份映射查询，不改写历史原始事件；关联记录迟到时结果可能更新，界面展示数据更新时间。首版不支持人工合并/拆分登录账号。

## 4. Browser SDK 接口与本地可靠性

### 4.1 对外能力

- init：endpoint、项目公开写入凭证、SDK 配置、错误/状态回调；初始化不阻塞业务页面。
- track(event_name, properties)：生成事件并异步排队；返回 queued-persistent、queued-memory 或 rejected，不把本地成功包装成服务端送达。
- identify、reset：按第 3 节处理身份；不自动读取业务 Cookie、姓名、手机号或输入框内容。
- flush：立即尝试发送队列快照，返回本次已确认/待重试/拒绝数量；不代表未来事件都已发送，不无限等待离线恢复。
- getQueueStatus：返回持久/内存记录数、字节数、最老待发时间、最近错误和存储模式。
- setConsent：业务方控制是否允许采集；默认初始化需明确传入授权状态。未授权不采集、不发送，不预先缓存个人数据；撤回时清空本地待发数据，已入库数据走服务端删除流程。

### 4.2 事件创建和本地存储

track 立即用安全随机源生成 UUID v4，快照身份、时间与属性，并启动 IndexedDB 写事务；事务完成才报告持久入队。序列化在调用时冻结业务对象，调用方随后修改对象不会改变已排队内容。落库前浏览器被杀死仍可能丢失，不承诺关闭钩子一定执行。

队列按 endpoint + project 隔离，只保存允许重试的完整事件、created_at、next_attempt_at、attempt_count、租约和字节数。凭证在请求时按当前配置附加，不给历史记录固化已撤销凭证。相同项目的多标签页通过原子事务领取有界批次和租约，不依赖永久存活的单一主标签页。

| 参数 | 首版默认值 | 行为 |
|---|---|---|
| batch_max_events | 20 | 达到即调度；队列更多时分批读取 |
| batch_max_bytes | 48 KiB | 按包含凭证和信封的最终 UTF-8 字节数计算；达到任一阈值调度 |
| flush_interval | 3 秒 | 有待发事件时计时；后台计时被节流不保证精确 |
| single_event_max_bytes | 16 KiB | 超限本地拒绝并报告，服务端同样校验 |
| fetch_timeout | 10 秒 | 超时结果未知，保留并重试 |
| max_inflight_per_tab | 1 | 普通上报并发；隐藏补发可能重叠但使用相同 ID |
| lease_duration | 30 秒 | 到期允许其他标签页重领；慢响应不得删除未确认的新记录 |
| local_queue_limit | 1000 条或 5 MiB | 先触达者生效；包含被租用记录 |
| local_queue_ttl | 7 天 | 到期不再发送，显式记录过期数量 |
| storage_fallback | 有界内存 | IndexedDB 不可用时启用，最多 100 条或 512 KiB |

以上为设计值，允许配置但由服务端公布硬上限；SDK 不允许配置出单条大于批次上限的组合。容量判断与持久入队需事务协调，避免多标签页突破上限。队列满默认拒绝新事件，不驱逐尚未确认的旧事件；公开 rejected_overflow、expired、storage_error 计数和回调。内存降级显式标记非持久，存储恢复时迁移到持久队列并保持原 ID。所有队列加起来仍有上限，不能隐式再建无界缓冲。

### 4.3 正常发送与错误处理

条数/字节阈值、3 秒定时、手动 flush、恢复联网、页面恢复可见、初始化回收旧队列均可触发。调度器尊重 next_attempt_at，不因多个触发器绕过限流退避；联网事件只触发尝试，不证明互联网或 API 可达。查询 pending 索引并领取有限批次，发送期间不持有 IndexedDB 事务。

只有收到合法的 HTTP 202 且 accepted_event_ids 与本批 ID 匹配，才删除这些已确认记录。其他响应和无法解析的成功响应均不删除。收到确认后删除失败，保留并下次重发；多个标签页重复确认的删除操作应幂等。

网络错误、超时、408、429、5xx 使用指数退避加随机抖动：初始基准 1 秒，指数上限 60 秒；429 优先遵守 Retry-After，时间更长时照常等待。尝试次数不作为静默删除依据，最终受 TTL/容量限制。

400 返回可定位的事件索引和代码，整批未进入 Kafka；SDK 将被拒事件移出可发送队列，报告 event_rejected，其余事件保留原 ID 重新组批。401/403 暂停项目发送并报告配置错误，凭证更新后可恢复。413 拆小批；单条仍超限则拒绝并报告。无法确定错误项的 400 暂停该批并暴露诊断，不无限刷请求。永久失败和容量过期均不进入 Kafka DLQ。

### 4.4 页面隐藏、关闭与恢复

监听 visibilitychange 的 hidden 状态；pagehide 作补充，不依赖 unload/beforeunload，不阻塞用户关闭或跳转。隐藏是“尽力补发”信号，不等于会话必然结束。

维护最多一个批次的内存发送快照；隐藏时用 sendBeacon 尝试发送，不等待关闭时才从 IndexedDB 大批读取。该快照可包含尚在异步持久化中的新事件；若 beacon 已排队但本地事务未完成仍不能保证恢复。每次 hidden 周期最多一次退出批次，pagehide 不重复放大请求；超出批次的记录留待后续恢复，不能承诺一次退出发完全部积压。

sendBeacon true 仅表示浏览器接受排队，不等于服务端成功，不删除本地事件。返回 false、跨域失败或浏览器退出均保留记录；首版不叠加无限 keepalive 重试。下次同源网站加载或页面重新可见时，回收过期租约并走普通 fetch 取得 202。BFCache 恢复不得重复初始化监听器和定时器。未读完的持久积压无法在退出瞬间保证发完。

浏览器端定位为尽力送达：存储被清理、隐私模式、配额不足、断电、强杀、拦截器或用户永不回访均可能造成漏报。没有后台常驻线程保证浏览器关闭后继续补发。关键订单/支付结果应从业务后端接入；需要事务保障时由业务系统结合自己的数据库 outbox，不依赖浏览器点击代替业务事实。

### 4.5 Node SDK

复用信封、批量与响应语义，提供可插拔持久 outbox；M1 提供单进程文件持久适配器及内存模式，文件格式需崩溃恢复验证并声明不支持多进程共享写。等待持久提交才返回 queued-persistent；不宣称 SDK 与业务数据库之间存在原子事务。shutdown/flush 有超时，不阻塞退出无限等待；生产关键事件推荐业务事务 outbox 集成。

## 5. 接入 API、Kafka 与消费者

POST /v1/batch 持续接收 SDK 主动推送，不轮询用户浏览器。UTF-8 text/plain JSON 信封包含 write_key、schema_version、events。常规 fetch 不携带业务 Cookie，服务端为配置的来源提供 CORS；支持 sendBeacon 无自定义鉴权头的同一协议。不在 URL 或访问日志记录凭证；仅接受 HTTPS。

| 响应 | 语义 |
|---|---|
| 202 + accepted_event_ids | 所有事件已被 Kafka 确认；可能尚未入库，也可能稍后进入 DLQ |
| 400 + 错误索引/代码 | 格式或项目 schema 无效，校验在生产前完成，整批不入 Kafka |
| 401/403 | 凭证无效、撤销或来源不允许，不能重试风暴 |
| 413 | 请求体超硬上限；接入硬上限 64 KiB，SDK 默认留足余量 |
| 429 + Retry-After | 租户配额/接入保护，未接收本批 |
| 503、超时或中断 | 未确认或结果未知；允许部分已进入 Kafka，复用 ID 重试 |

先检查请求体、凭证、Origin、schema、单事件大小和配额，再生产 Kafka。服务端批次最多 100 条；这些是协议限制，不是吞吐承诺。写入凭证仅能接入，查询与管理用独立身份认证。无 Cookie API 的 Origin 校验不构成防伪，配合速率、字节和租户配额控制滥用。

接入 API 不为去重逐条查询 PostgreSQL，允许相同 ID 多次进入 Kafka。生产按 project_id + distinct_id 哈希分区；每分区有序不代表全局有序，客户端并发和重试也不能保证事件按发生时间抵达。

消费者流程：校验/标准化 → 事务登记去重键 → 新事件写原始表及聚合任务 → COMMIT → 提交对应分区连续完成的 offset。SQL 唯一约束解决并发，不能“先查再插”替代。数据库事务失败不提交 offset；COMMIT 后 offset 前崩溃会重放，但不重复计数。

| 情况 | 消费者行为 |
|---|---|
| 同 project、同 ID、同规范化载荷 hash | 跳过重复写入与聚合，计 duplicate，允许推进位点 |
| 同 project、同 ID、不同 hash | 保留首条，持久写 DLQ/冲突记录并告警，成功后推进位点 |
| 毒事件或确定不可处理的业务载荷 | 写 DLQ，附失败原因、schema/处理器版本、来源 topic/partition/offset |
| 数据库断连、死锁等临时故障 | 有界重试、暂停分区，不将所有事件转入 DLQ |
| DLQ 不可用 | 暂停，不跳过问题记录，不提交越过它的连续位点 |

hash 使用规范化 JSON（稳定键顺序、固定字段集合），包含 event_name、身份快照、event_time、properties、稳定 context；排除 received_at、write_key、重试次数等传输信息。schema 更新不得让已接收事件仅因“最新规则变化”无限失败，保留接收时版本并提供版本化处理。

## 6. 数据存储、保留与重放

核心实体：tenants（公司/工作区）、users（平台账号）、tenant_memberships（公司成员关系）、projects、write_keys（存 hash）、event_schemas、event_dedup、按时间分区的 events、identity_links、aggregation_jobs、reports、dashboards、query_jobs、deletion_jobs、audit_logs。公司成员关系和公司级配置带 tenant_id；项目及所有项目数据同时带 tenant_id 和 project_id，埋点用户身份仍以项目为作用域，与平台登录账号分开。

所有公司共享 PostgreSQL，但数据归属必须显式保存；projects 提供 (tenant_id, project_id) 唯一归属键，相关数据通过组合外键/约束验证公司与项目匹配。去重键仍为 (project_id,event_id)，因为 project_id 全平台唯一且项目不允许跨公司迁移；去重记录也携带 tenant_id 并受相同隔离。不同公司或项目使用相同 event_id 不互相去重，不影响计数。

event_dedup 以 (project_id,event_id) 唯一，不依赖原始事件时间分区约束；存 payload_hash、首次接收时间与处理状态。原始事件用 UTC event_time 分区，保存 received_at 以追踪延迟；登记、新事件、聚合任务在同一 PG 事务。异步聚合以幂等任务和受影响时间桶重算，不能每次消费都无条件累加。

| 保留项 | 首版默认设计 |
|---|---|
| SDK 本地事件 | 7 天 |
| 普通 API 最早事件时间 | 接收时往前 7 天；未来最多 5 分钟，越界拒绝并报告时钟问题 |
| Kafka events | 目标 72 小时，同时设容量上限；容量可能先触达，必须监控最老可用位点 |
| Kafka DLQ | 目标 14 天，同时设容量上限；需要修复/导出并告警，不能当永久归档 |
| PG 原始事件 | 30 天 |
| 去重登记 | 至少 45 天；去重登记过期前须覆盖所有准入重试/重放窗口 |

以上保留组合仅为小规模起点，部署前根据字节预算校验，1 GB 试验机不能自动照搬容量。普通 SDK 不接受任意历史导入。DLQ 管理重放最大原事件年龄 30 天且去重登记仍在；更老导入必须进入单独审计迁移流程，首版不开放。

重放任务保留原 event_id，记录操作者、原因、范围、数量和结果；同 ID 异载荷冲突不允许直接修改后重放，需人工确定原始事件有效性，避免覆盖首条。消费程序修复后的原载荷重放允许。重放不自动删除 DLQ 原记录，记录处理状态；同一重放任务重复执行不得增加统计。

## 7. 分析功能与统一口径

所有查询必须有已授权的公司范围、项目范围、时间范围和身份映射规则；用户选择项目时区（默认 Asia/Shanghai），数据库保留 UTC。日/周/月桶按项目时区换算，区间采用左闭右开。修改时区后的重新查询按新时区重算，已保存报表记录所用时区。

| 功能 | 首版行为与口径 |
|---|---|
| 事件探索 | 按事件名、时间、用户、属性筛选；分页查看原始去重事件；空值与缺失字段分开处理 |
| 用户时间线 | 按规范化用户查询，显示 event_time、received_at、ID 和来源；同时间以 event_id 稳定展示，不代表真实发生先后 |
| 趋势 | 总事件次数、去重用户数、数值属性 sum/avg；无效或缺失数值不计入分母，显示排除数；折线/柱状/表格 |
| 漏斗 | 2–5 步，严格有序但允许中间有其他事件；同一规范化用户，时间窗口默认 24 小时；各步 event_time 严格递增，相同时间不推断先后；首步发生在所选时间范围，可向结束后延伸一个窗口；每用户计一次转化，搜索最早可完成的序列，分组取该序列首步属性 |
| 留存 | 按首次满足起始事件的日期形成 cohort；返回事件可配置；第 N 个项目时区自然日是否回来，按用户计一次；未观察完整的日期标为未成熟，不当作 0；首版精确日留存，不混用滚动留存 |
| 分群 | 动态规则：时间范围内做过/未做过某事件、次数阈值及事件属性条件；未做过的用户集合以项目当前保留期内已出现身份为基础；不承诺全量历史用户库 |
| 仪表盘 | 保存趋势/漏斗/留存卡片、布局、筛选；显示查询时间、数据新鲜度和失败状态，允许带时间戳的旧结果 |

属性筛选支持等于、不等于、集合包含、存在/不存在、数值比较；不等于默认不包含缺失字段。首版分组最多两个维度、最多返回 20 个组及 other，用户可查看截断说明，避免误以为只有展示的组。数值比较不隐式把任意字符串转成数值。

留存的“首次”指当前所选起始时间范围内首次满足起始事件，不宣称是用户全生命周期首次。历史数据超出保留期时无法还原全生命周期；漏斗窗口或留存观察区间落在尚未到来/已过期的数据范围时显示数据不完整，不能默认为未转化或未留存。

迟到事件落库后影响原事件时间桶，相关趋势/身份关联结果重新计算；漏斗/留存必须查询去重原始数据或经验证等价的结果。所有图表显示 computed_at 和数据积压，不能承诺某个时点已经绝对完整。

## 8. 权限、隐私与数据删除

### 8.1 公司隔离与角色

一个工作区对应一家公司，可包含多个项目；公司内所有有效成员均可查看全部项目、事件、用户时间线、报表、仪表盘和分析结果。员工与老板的数据可见范围相同，不做员工、部门、门店或项目级数据范围配置。首版查询以单项目为单位，不要求跨项目合并分析。

| 公司角色 | 数据可见范围 | 操作权限 |
|---|---|---|
| admin（含公司创建者） | 本公司全部项目和分析数据 | 管理成员、项目、凭证、删除任务及 DLQ；创建和修改报表 |
| analyst | 本公司全部项目和分析数据 | 查询、导出、开发调试、创建和修改公司共享报表；无成员/凭证/删除/DLQ 管理权限 |
| viewer | 本公司全部项目和分析数据 | 只读查询和查看共享报表；无配置、修改或管理权限 |

角色只限制操作，不细分数据范围；报表首版均为公司内共享，不设计私人报表访问控制。普通员工可默认邀请为 analyst。用户可以加入多个公司，但请求必须明确当前公司上下文；每次检查目标公司的有效成员关系和相应角色，不能因在 A 公司是 admin 就获得 B 公司权限。移除成员后后续 API 请求和任务结果下载立即按新权限拒绝，不能只在登录时检查一次。

后台采用独立平台账号登录，禁止默认公共注册。平台初始化管理员通过一次性部署流程创建，用于开通公司和首位公司管理员；该管理身份不自动具有各公司事件查询权限。首版不提供隐式跨公司“超级查看”，运维直接访问数据库属于独立受控操作。

### 8.2 隔离在各链路的执行

- 接入：write_key 唯一绑定 tenant_id + project_id；服务端解析可信归属后附入 Kafka 信封，载荷中的伪造归属字段拒绝。写入凭证只允许接入，不能查任何公司的数据。
- 查询/修改：从登录身份、当前公司和 tenant_memberships 验证授权，项目 ID、报表 ID、任务 ID 必须再次校验属于该公司；前端传 ID 不授予权限。未知或跨公司对象统一返回 404，不泄露对象存在与否；未登录返回 401。
- 数据层：仓储接口必须接收已验证 tenant scope，所有查改删带公司条件；组合归属约束防止写入错配。代码评审和集成测试覆盖原始 SQL、聚合和后台任务，不只检查页面。
- Kafka/Worker：只信任接入端附加的公司归属，消费写入验证项目与公司一致；DLQ、重放和审计记录同样带公司范围。
- 异步查询、导出和下载：任务携带公司/发起者上下文，执行与读取结果时均重新鉴权；文件由受保护下载接口提供，不生成可绕过权限长期公开链接。删除/重放操作另检管理角色。
- 所有派生结果：聚合桶、查询任务、缓存键（如启用）、导出存储路径均带 tenant_id 和 project_id，不能仅按报表名、用户 ID 或查询文本复用。成员变更后不得从缓存继续读取越权结果。
- SDK 本地队列继续按 endpoint + project 隔离；事件所属公司由该项目写入凭证确定。平台不得把 A 公司的失败事件、用户属性或 DLQ 载荷出现在 B 公司的监控界面；全局运维指标只展示脱敏汇总。

### 8.3 隐私与删除

公开写入凭证可轮换和撤销，不授予查询权限；服务端管理会话使用安全 Cookie、CSRF 防护与登录速率限制。查询只接收结构化 DSL，服务端参数化 SQL 和字段白名单，不执行用户 SQL。SDK 不默认采集输入框、完整 URL 查询参数、Cookie、令牌、姓名/手机号；属性采集责任在接入方，提供敏感键过滤与允许字段配置。

项目默认启用隐私过滤；调试日志不输出凭证或完整事件载荷，DLQ 数据受同等权限和保留策略保护。写入流量限额与采样分开；首版不默认采样，丢弃/拒绝均可观察。

管理员可按用户（包含已关联匿名身份）或项目发起删除，展示 queued/running/completed/failed。删除原始事件、身份映射、相关明细缓存与导出，并使受影响聚合失效重算；保留受限删除审计。Kafka/DLQ 未过期记录不能逐条即时物理擦除，消费者通过项目/身份删除屏障拒绝重新导入，最长保留窗口结束前显示 pending-stream-expiry。删除屏障至少保留到旧 SDK、Kafka 和 DLQ 准入窗口结束；删除前创建的用户事件不得因重放复活。备份遵循保留期自然过期，恢复后必须重放删除清单。不能把仅删除 PG 数据的时刻标为全链路物理擦除完成。

## 9. 容量、降级与部署

当前试验机资源约 1 vCPU、961 MiB RAM、1 GiB Swap、20 GB 磁盘，重装后检查约 16 GB 可用。用户接受在此尝试完整低流量链路，但成功启动不等于容量验收，不因试验配置改掉 Kafka 或 PostgreSQL，也不引入 Redis。

构建与打包在本地/CI 完成；前端可放 Cloudflare 静态托管。API/Worker 可合进同一个部署进程但模块分离，Kafka 和 PG 独立持久卷并设资源预算。Kafka 单节点 KRaft，RF=1/min ISR=1；不具备副本高可用。不得用关闭 fsync/WAL、虚假 202 或静默采样来换取运行成功。内存与磁盘不满足启动/恢复安全余量时停止负载测试，报告瓶颈，再调整规格。

Cloudflare 作为可选 DNS/HTTPS/防护入口和 R2 备份目的地，不缓存埋点 POST，不改变 202 确认边界；额度、可达性和跨域行为部署时复核。不要求 Cloudflare Workers 承担接入链路。

| 压力/故障 | 降级 |
|---|---|
| 查询占用高 | 先限查询范围与并发，返回带时间戳旧结果，重查询进入异步任务 |
| PG 暂不可用 | 暂停消费、Kafka 缓冲；预计保留窗口/磁盘将耗尽时提前拒绝新接入 |
| Kafka 不可用/ISR 不足 | 503，SDK 重试；不自动双写 PG |
| SDK 存储不可用/满 | 有界内存降级或拒绝新事件，回调报告，业务继续运行 |
| 单机损毁 | 异机备份恢复；异步备份间隔存在 RPO，不承诺零丢失 |

查询默认最大范围 30 天、同步超时 5 秒、每项目同步并发 1（试验配置），最多 50 张仪表盘卡片且按队列加载；超时返回可识别状态，可提交异步查询。资源预算可配置，异步任务也有并发和最长时间限制，不允许无限积压。

容量计算包含原始事件、JSON/索引放大、去重登记、WAL、Kafka 日志/副本、DLQ、备份和系统保留空间；不只计算事件正文。生产升级至多接入实例、跨故障域 Kafka 三副本与 PG 主备时另行验证故障模型。

## 10. 监控、验收与发布门槛

必须记录 SDK 入队/拒绝/过期/溢出、存储模式、发送与重试；API 按状态码的批次/事件数、确认延迟；Kafka ISR、分区 lag、最老可用记录与消费位点距离；PG 写入失败/耗时、重复/冲突；DLQ 进入/重放/未处理年龄；查询耗时、任务积压；CPU、RSS、Swap 活跃度、磁盘余量与备份恢复结果。SDK 自身诊断发送不得再次进入 track 造成递归；离线诊断不保证服务端可见，getQueueStatus 和本地回调可用。

浏览器验证覆盖发布时 Chrome/Edge/Firefox/Safari 当前及上一稳定主版本，含移动 Safari 与 Android Chrome 的真实关闭/后台切换场景；支持 IndexedDB 被禁用和 BFCache 恢复。最终支持矩阵随 SDK 发布固定，不凭模拟关闭事件宣称全部浏览器通过。

| 编号 | 场景 | 验收结果 |
|---|---|---|
| A01 | 同一用户两个操作；两用户同时操作 | 每次操作 event_id 不同，身份快照正确 |
| A02 | 单事件未满阈值，页面持续可见 | 定时调度发送；普通响应确认后删除对应本地记录 |
| A03 | 连续事件达条数/字节阈值 | 有界拆批、最多一个普通在途请求，不全量读取积压 |
| A04 | 离线创建事件，刷新再联网 | 已提交的 IndexedDB 记录恢复，原 ID 重发，统计各一次 |
| A05 | 隐藏时 beacon true/false，两种情况再访问 | 未拿 202 均保留；普通 fetch 确认后清理；PG 不重复计数 |
| A06 | 正常请求已接收但响应丢失，或删除本地记录前关闭 | 下次重发可确认，不增加事件次数、用户数或聚合贡献 |
| A07 | 双标签并发发送、崩溃遗留租约、BFCache 恢复 | 租约回收，不永久卡住；无重复监听器/无限发送；重叠仍只计一次 |
| A08 | 多用户切换且旧队列未清空 | 旧事件身份不变，reset 后新匿名身份不同，不串号 |
| A09 | IndexedDB 不可用、队列满、TTL 到期 | 显式回调、容量受限、业务不崩溃；不宣称事件已送达 |
| A10 | 400、401、413、429、超时、5xx | 分别按协议拒绝/暂停/拆批/退避，不误删待发记录 |
| A11 | 相同事件并发落库 | 唯一约束保证仅一条原始记录和一次聚合贡献 |
| A12 | 相同 ID 不同载荷 | 首条保留；冲突可查询并告警，不覆盖、不当作正常重复 |
| A13 | Worker 在 COMMIT 前/后、提交 offset 前被杀 | 前者回滚，后者重放去重；不跳过未完成的较低 offset |
| A14 | Kafka 批次部分成功、API 未确认 | SDK 整批复用 ID 重试，最终无重复计数 |
| A15 | PG 不可用、毒事件、DLQ 不可用 | 临时故障暂停；毒事件仅在 DLQ 确认后越过；DLQ 失败不跳过 |
| A16 | DLQ 同一任务重放两次，或去重记录过期 | 窗口内幂等；过期拒绝普通重放，要求审计迁移 |
| A17 | 趋势/漏斗/留存固定数据集 | 覆盖身份关联、同时间事件、跨日/时区、迟到和未成熟 cohort；与定义一致 |
| A18 | 两公司各建两个项目，分别以 admin/analyst/viewer 登录 | 每个角色均可查看本公司两个项目；角色仅限制操作；均不能读取其他公司数据 |
| A19 | 删除用户后重放旧 Kafka/DLQ，恢复旧备份 | 删除屏障生效，不复活数据；状态明确标注流保留/备份边界 |
| A20 | 真实关闭、强杀、离线不回访 | 展示送达与漏报边界；不以浏览器全部送达为验收承诺 |
| A21 | 篡改 tenant_id/project_id、报表/导出/任务/DLQ ID，猜测其他公司对象 | 全链路无越权；对象统一 404；无跨公司缓存、文件或错误信息泄露 |
| A22 | 同一平台账号加入 A/B 公司，在 A 为 admin、B 为 viewer；随后移出 B | 切换公司后只使用当前公司角色；移除后不能继续查询或下载旧任务结果 |
| A23 | 不同公司发送相同 event_id；伪造公司归属；重放跨公司 DLQ | 合法事件分别计数；归属错配拒绝且有审计；不能跨公司重放或删除 |

容量验证：本地/CI 先做协议和故障测试；试验机从 1 EPS、平均约 1 KiB 的受控合成事件起步，同时每 10 秒执行一次趋势查询，持续 30 分钟，再按资源逐级增加。对账必须用稳定 event_id 而非 Kafka 消息总条数（包含重试）。停止生成后，测试样本的唯一 ID 应全部归入 PG 或有原因的 DLQ，无重复计数，积压应可清空。

初步发布目标：上述受控场景无 OOM/进程重启、无未解释事件缺口、无持续 Swap 换入换出，磁盘至少保留 20% 余量；健康场景接入 p95 < 1 秒、端到端可查询 p95 < 10 秒、30 分钟内积压不持续增长。它们是待验证目标，不是已达 SLA 或生产吞吐承诺。未通过则降低测试负载/减少非必要开销或升级资源，不降低数据确认标准。

发布前必须演练从异机备份恢复，记录实际 RPO/RTO、恢复耗时和测试条件；生产 SLO、实际 EPS、保留容量与预算在容量报告后确定。原始已接收样本应按唯一 ID 对账：正常落库、DLQ/冲突、仍在 Kafka 待处理各有明确去向；SDK 未被持久接收的拒绝/过期与之分开统计。

## 11. 待实测与后续决策

业务量、峰值和事件大小；试验机 Kafka/PG 可用内存预算；磁盘写性能和公网带宽；事件保留容量；生产 RPO/RTO；跨域退出发送的浏览器矩阵；SDK 体积、主线程序列化耗时和 IndexedDB 延迟。未确定项不阻塞本地实现，但发布前必须量化，不预先编造并发承载能力。

SDK 性能验收采用相同页面“未安装/安装但空闲/20 EPS 合成操作”对照，记录包体 gzip、track 同步阶段 p95/p99、长任务、队列读取量和本地写耗时；首个目标 gzip ≤ 30 KiB、1 KiB 事件 track 同步阶段 p95 ≤ 2 ms（明确测试设备）。持久化与网络耗时单独测量；未达标再优化，不写镜像实现的无效测试。
