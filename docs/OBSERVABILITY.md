# 监控记录与边界

实施依据为 PRD 第10节。此文件区分已记录的信号与尚未完成的监控，不能把一组绿色状态替代完整发布门槛。

## 当前已有信号

项目 `GET /metrics` 为 PostgreSQL 持久累计计数，包括成功插入、重复、删除屏障及保留清理等。它们不是当前保留行数或所选日期的事件数；缺失项表示未记录，不能推断为0。同公司有效成员可读本项目数据，外公司不可读。

管理员 `GET /ingest-status` 返回脱敏接入保护及 Kafka lag 汇总，保留量属于当前 API 实例。前端投递监控会区分这些范围，读取失败清除旧快照，权限失效清除项目数据；页面是状态观察，不提供解除完整性门禁的按钮。

## 步骤105：API响应计数与处理时间（尚未部署）

仅统计进入 Hono 的 `POST /v1/batch`；OPTIONS、TLS/Nginx提前拒绝等不在该计数中。每次路由完成后记录其实际响应状态，包括请求体413和错误处理器503。状态桶固定为202/400/401/403/413/429/500/503/other，避免标签增长。

每状态记录批次数、已知请求事件数、事件数未知的批次。事件数只在凭证已查到、events是数组且数量在协议上限内时取得，拒绝的无效事件仍可能属于已知请求数；这不是有效事件或独立event_id数量。重试的202会再次增加请求计数，业务是否重复由Worker幂等登记决定。凭证未查到或不可解析的请求不会被假装成0事件。

202处理时间使用单调时钟，从Hono接入中间件到构造响应完成，包含请求体读取、校验、凭证查询及等待Kafka结果；不含TLS、代理/网络回程、客户端收到202或PG可查询延迟。固定毫秒上界1/5/10/25/50/100/250/500/1000/2500/5000/10000/30000，以及最后一个无界桶（JSON上界null）。桶是互斥频数，不是Prometheus累计桶；无效时间样本另计unknown，不能当作0ms。

计数为BigInt转十进制字符串。每进程生成独立instance_id、启动/观察时间，并标明`api_instance_aggregate`及`cumulative_since_process_start`。这是该API实例跨公司的脱敏汇总，不是某公司、全体接入实例之和或最近15分钟分布。多实例应按instance_id区分；重复日志快照不能逐帧相加。

API主进程每10秒输出一份`intake_metrics`结构化累计快照，正常停服排空HTTP后再输出末份；不逐请求写日志或在确认路径写PG。管理员状态接口附带同一实例快照。记录中没有写入凭证、用户/事件ID、属性、原始载荷及公司/项目ID。角色、成员和项目范围校验在读取快照之前完成。

指标回调即使同步抛错或异步拒绝，也不能把已获Kafka确认的202改为失败；发布失败仍503，指标不能制造确认。日志输出与快照是运行遥测，**不是业务持久账本**：SIGKILL可能丢最近未输出部分，重启会换instance_id并从0开始，Docker日志有旋转上限。持久时序目的地、跨实例汇总、告警及历史SLO仍待完成；不据此承诺完整历史或恰好一次遥测。

目前Worker维护完成/忙/安全错误码已有结构化日志，但持久最近成功状态、全量写库时延、DLQ未处理年龄、查询积压/资源及备份监控面板仍须补齐。当前VPS容量仍未通过持续Swap门槛。

## 步骤106：解析与鉴权前的请求处理预算（尚未部署）

每API实例默认最多同时处理16个POST/v1/batch，通过INGEST_MAX_INFLIGHT配置，必须为1–128整数，非法配置在监听前失败。同步占用名额后才进入请求体大小检查/解析和PG鉴权；无等待队列，超额立即503 ingestion_paused/intake_concurrency_full及Retry-After:5，仍带SDK可读CORS头。该拒绝不读取正文、不访问PG或Kafka，事件数遥测因此为未知。已进入的请求不因后续饱和被撤回确认，解析/鉴权/发布错误都在finally归还名额。

这是当前实例的请求处理数预算，不是TCP连接数、吞吐承诺、全平台配额或完整DDoS方案。字节/来源/公司速率/Kafka与磁盘保护继续独立执行。满载时超额无效正文也先得到可重试503，名额恢复后才执行原来的永久错误校验。OPTIONS及存活检查不占上报名额；就绪仍反映依赖/完整性，短时处理名额不足采用逐请求503。

管理员状态快照新增本实例in_flight/max_in_flight/at_capacity；前端同时考虑该预算和Kafka保护，不会在Kafka允许但名额满时显示允许接入。该快照仍需成员/项目及admin授权，不能用于解除门禁。客户端沿用既有503稳定ID重试，无需更改确认标准。尚未测量本设置在VPS上的负载，不把默认16视为已获容量认证。

## 步骤110：Worker操作观测（尚未部署）

Worker每10秒输出`worker_metrics`脱敏进程累计快照，正常关闭在consumer.disconnect完成后输出末份；instance_id区分进程重启，不能逐帧相加。固定四类操作：persist为一次完整事件写库调用（连接等待、事务、隐私锁、提交或回滚均包含）；dlq_publish仅Kafka DLQ发布确认；dlq_index为PG DLQ登记调用；kafka_checkpoint仅Kafka提交下一消费位点。独立PG消费进度事务、聚合/维护及端到端可见时间不包含在这些耗时里。

persist成功区分inserted/duplicate/suppressed，EventConflict记conflict，其余异常记failed；其他操作完成记completed，抛出记failed。错误仍按原路径重试/抛出，原异常对象不改变，不通过指标推进位点。重试会增加调用计数，故不是唯一事件数或最终DLQ数量；失败发布或索引不能被计为完成。固定非累计毫秒桶为1/5/10/25/50/100/250/500/1000/2500/5000/10000/30000及无界null，所有结果共享该操作耗时分布；单调时钟无效样本单独计数。in_flight可揭示尚未完成的长调用，当前时长不作为已完成样本。

快照不含tenant/project/user/event ID、offset、错误文本或事件载荷；固定操作/结果标签避免随业务增长。日志失败和分类回调异常不能改变处理结果。SIGKILL可能丢最后窗口，重启计数归零，日志有旋转上限；当前无API跨进程读取或持久时序存储。DLQ未处理年龄、持久告警、PG进度耗时及全量监控仍未完成。单测验证观测器，尚未在VPS对本版Worker故障注入，不能据此宣称完整链路验收。

## 步骤111：项目DLQ保留记录分类与年龄（尚未部署）

管理员GET项目路径`/dlq-summary`读取单条SQL一致性快照，返回四类十进制count、oldest_created_at、oldest_age_seconds与数据库observed_at。范围仅当前公司/项目且创建时间未超过14天，无scope的DLQ不混入某公司。未登录401、非admin403、跨公司项目404，与DLQ载荷权限一致。

优先级：载荷已redacted或有suppressed重放记录→suppressed；曾有stored/duplicate成功回执→resolved；否则有queued/published记录→replaying；其余→unresolved，包括没有重放及失败/拒绝重放。历史失败不覆盖成功回执；活动请求不等于成功。统计的是仍保留的原DLQ来源及其回执，不是唯一业务事件、永久故障累计、实时重放可行性或Kafka DLQ总量；同一事件可能产生多个来源，过期不代表修复。空类别count为0、时间/年龄null；未来时间年龄钳制0，年龄由数据库时间计算，避免工作站时钟差。

仅返回四个固定类别及聚合时间，不返回payload/ID/原因文本。使用既有created_at与replay source索引，受PG 5秒statement timeout约束；大规模DLQ下的查询成本尚待容量验证，不声称无界规模可用。暂未接入监控UI/告警，下一步继续完成展示和运行验收。

步骤112已在源码投递监控页面接入：仅管理员请求DLQ摘要，展示保留来源分类、精确数量、最老来源年龄（秒）及数据库快照时间。0条对应无记录，缺失对应未记录。手动刷新及可选可见时轮询，失败或失权清除旧DLQ数据；公司/项目切换卸载旧组件并中止请求。Chrome模拟API验证失败/恢复、公司切换、viewer不请求和窄屏布局；尚未部署VPS，也未完成持久告警及真实本版Worker运行验证。

## 步骤116：可见查询任务积压快照（未部署）

公司有效成员可GET项目`/query-status`，与同项目query-jobs列表使用相同的未过期、当前privacy_epoch、创建者仍为公司成员过滤。五个固定状态queued/running/succeeded/failed/cancelled，各返回精确字符串count、最老created_at及其数据库年龄；running另返回从最老有效started_at计算的oldest_running_seconds。空类别时间/年龄null，未来时间钳制0。不是全平台队列、接入限额占用或已隐藏任务计数；管理员也不能据此推断其他公司或失效创建者任务。

duration_samples及max_completed_duration_ms仅使用started_at存在且finished_at>=started_at的记录，覆盖完成/失败/取消，不把未开始或无效时间当0。时长从开始执行到状态完成，不包含排队，不证明取消已中断SQL；running年龄是读取时观察，既非已完成耗时也非死锁判定。默认任务24小时过期，隐私变更和成员撤销会改变统计样本，因此这些是当前可见保留记录统计，不是稳定历史SLO。单SQL一致性快照、PG 5秒超时；不读取spec/result或返回用户/任务ID，未新增索引，规模成本待测。界面、历史与告警仍待接入。

步骤117已接入源码投递监控：所有有效角色可读项目查询状态，展示五状态、最老任务年龄、最老运行已执行时间与终态耗时样本/最大值。采用数据库快照时间，刷新后更新，不把运行中的时间计入完成耗时。整数和小数均精确文本格式化，缺失显示未记录、0条无任务、0有效样本无有效样本。失败/失权/项目切换清除旧快照；Chrome mock验证通过。尚未部署，持久历史和告警仍待完成。
