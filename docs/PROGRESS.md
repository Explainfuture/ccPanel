### 修复 10：消费恢复与真实故障演练

数据库写入失败时在消费位点前退避并维持心跳，意外非自动恢复的消费者崩溃退出交给进程监督器；毒事件保留原载荷，非法归属不会让 DLQ 索引写入永久卡在 UUID 转换。API 增加周期性 Kafka 就绪探测，接收成功仍必须以实际生产确认作为依据。

VPS m4-recovery-001 完成受控演练：暂停 Worker 后已确认事件留在 Kafka；恢复后入库；真正停 PG 时日志出现写入重试且消费位点不前进；恢复 PG 后追赶；停 Kafka 时 API 返回503而非虚假202；恢复后原ID重试成功；毒事件进入DLQ。测试用独立公司，结束清理测试夹具。修正 Compose 启动 Worker 默认拉起 PG 的演练陷阱，使用 no-deps 并断言 PG 确实停止。

演练后 Kafka/PG/API/Worker 正常运行。另启用 Fail2Ban SSH 登录防护，保留已授权登录方式。上述是受控服务中断测试，不替代 COMMIT 窗口强杀、断电、磁盘满、备份恢复和连续容量验收。
